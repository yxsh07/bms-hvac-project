# ADR-003 — SimSite: calibrated physics-lite, not magic ML

**Status** Accepted · **Task** T-016/T-017 · **Plan** §3.2, §6

## Honest description

SimSite is calibrated physics-lite plus replayed shapes, **not** forecasting.
Three days of data cannot support prediction (R6). It reproduces the §3.2
targets and nothing more.

## State and equations

- **Weather**: diurnal dry-bulb curve between profile min/max plus a slider
  offset; RH moves inversely; wet-bulb via the Stull approximation.
- **Zones**: first-order RC, `C·dT/dt = (T_out − T)/R + Q_int − Q_cool`,
  `Q_cool = valve × Q_max`; the valve follows a PI controller with anti-windup
  toward the thermostat set point. Vectorised in numpy.
- **Plant**: CHW load = Σ valve × Q_max → TR; flow chosen so
  `ΔT = Q / (1.163 · flow)` emerges near 3 K at part load; staging is lead
  always on, lag in above ~85 % for 10 min and out below ~55 % for 15 min,
  10-min minimum on/off, standby promotes on a trip.
- **Chiller power**: `kW = TR × eff(PLR, T_cond_ent, T_chw_leave)`, a quadratic
  in PLR plus a condenser term tuned so the mean efficiency matches ~0.47
  ikW/TR. The condenser sensitivity (≈2.5 %/K) is an **assumption** and is
  flagged as such when active. A gradient-boosted surrogate is out of scope for
  the synthetic seed and the parametric curve is used throughout.
- **Tower**: `approach = a0 + a1·load (+ fouling)`; `T_cond_ent = T_wb + approach`.
- **Counters**: cumulative kWh/kVAh integrate monotonically; the fault layer may
  reset them.

## Time stepping and determinism

One sim-minute per step (Euler is valid because the zone RC is hours; assert
`dt ≤ RC/10`). Checkpoints every sim-hour; `seek` restores the nearest earlier
checkpoint and re-runs ≤ 60 steps. Noise is a stateless hash of
`(seed, entity, field, t)`, so replay and seek are exact and the same seed
produces an identical export.

## Fault layer

Faults mutate the **emitted rows only**; the physics state stays truthful, so
the app's quality layer is tested against known ground truth. Types: sentinel,
out-of-range, dropped-polls, delayed-backfill, orphan, stopped-zero (also a
baseline for flagged assets), contradictory, controller-outage, counter-reset,
flatline, negative-kw, plus scenario faults (trip, valve-saturation,
low-delta-t, tower-fouling).

## Assumptions

- The seed ontology is small (7 central assets), so absolute TR/kW are small;
  the acceptance tests assert the **ratios** from §3.2 (ΔT, ikW/TR, runtime
  share, dropped-poll rate) rather than absolute magnitudes.
- Logical scenario targets (`lead-chiller`, `critical-ahu`, …) resolve to real
  ids by asset `type`; the seed has no `criticalAhu`/`vav` types, so those fall
  back to the first `ahu`/`fcu`. This is a seed-data gap, not an engine rule.
- The floor-kW-includes-plant question (§3.1) is unresolved and recorded in
  `data/calibration/README.md`.
